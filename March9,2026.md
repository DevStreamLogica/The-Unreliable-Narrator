 THE UNRELIABLE NARRATOR — Complete Code Analysis                                                                                                                    
                                                                                                                                                                      
  Files scanned: 38 Java files + 5 docs | Lines of code: ~8,000+ | Engine: LibGDX (1280×720, LWJGL3)
                                                                                                                                                                        ---                                                                                                                                                                   EXECUTIVE SUMMARY                                                                                                                                                                                                                                                                                                                         
  The game is architecturally ~90–95% feature-complete. Core narrative, state management, tape progression, interview system, awareness mechanics, and saving/loading
  are all implemented. The biggest concerns are: 4 confirmed crashes waiting to happen, achievements are never saved, GameState has a save/load corruption bug, and     GameScreen.java (1,920 lines) is a fat controller that desperately needs splitting. The game should not crash in a normal playthrough, but edge cases will hit NPEs
  and there are silent failure modes everywhere.                                                                                                                      
  
  ---
  CRITICAL BUGS (Will Break the Game)
                                                                                                                                                                      
  1. AchievementSystem — Achievements Never Persisted
                                                                                                                                                                        File: AchievementSystem.java | SaveLoadSystem.java                                                                                                                                                                                                                                                                                          Achievements are tracked in an in-memory Set<Achievement>. SaveLoadSystem never serializes or deserializes the achievement set. If the player quits after unlocking   SPEEDRUN or GHOST, those achievements are gone on next load. This is a complete implementation gap.
                                                                                                                                                                        Fix: Add unlockedAchievements to SaveLoadSystem's SaveData inner class and serialize/deserialize it.                                                                  
  ---                                                                                                                                                                 
  2. GameState.clearAllState() — Entrance Visit Count Bug
                                                                                                                                                                      
  File: GameState.java line ~265
                                                                                                                                                                        After calling clearAllState() (which is used by SaveLoadSystem.load()), the loop resets all visit counts to 0 — including ENTRANCE. But the constructor sets          ENTRANCE to 1 (player starts there). The load path never re-increments ENTRANCE to 1, so after loading any save, the ENTRANCE visit count is 0 instead of 1. This   
  affects room description logic in RoomDescriptions.getDescription() which uses visit count for dynamic text.                                                        

  Fix: After visitCounts.put(id, 0) loop in clearAllState(), add visitCounts.put(Room.RoomID.ENTRANCE, 1);                                                              
  ---                                                                                                                                                                 
  3. DocumentReconstructionGame — Null Callbacks Crash on Fire
                                                                                                                                                                      
  File: DocumentReconstructionGame.java lines ~243, 251
                                                                                                                                                                        finish() calls onComplete.run() and cancel() calls onCancel.run() with no null checks. If GameScreen ever starts the mini-game without setting both callbacks, this   is an immediate NPE. Given how complex the interaction is (pendingMiniGame state flag → text panel close → startPendingMiniGame()), this is a realistic crash path. 
                                                                                                                                                                        Fix: Guard both: if (onComplete != null) onComplete.run();                                                                                                            
  ---                                                                                                                                                                 
  4. SaveLoadSystem.setChosenEndingByName() / GameState — Enum Crash on Corrupt Save
                                                                                                                                                                      
  File: GameState.java line 285
                                                                                                                                                                        Ending.valueOf(name) throws IllegalArgumentException with no catch. If the save file has a renamed or invalid ending value (typo, old save from before a rename),     the game crashes to desktop on load.                                                                                                                                
                                                                                                                                                                        Fix: Wrap in try/catch and fall back to Ending.NONE.                                                                                                                  
  ---                                                                                                                                                                 
  5. AwarenessMeter — Array Out of Bounds
                                                                                                                                                                      
  File: AwarenessMeter.java line ~53
                                                                                                                                                                        COLORS[system.getColorIndex()] — getColorIndex() in AwarenessSystem maps percentage to 0–3. The COLORS[] array has 4 entries. If awareness is exactly at              MAX_AWARENESS (80) or the percentage calculation returns exactly 1.0, the index could go to 4 → ArrayIndexOutOfBoundsException.                                     
                                                                                                                                                                        Fix: Clamp: COLORS[Math.min(system.getColorIndex(), COLORS.length - 1)]                                                                                               
  ---                                                                                                                                                                 
  HIGH SEVERITY BUGS
                                                                                                                                                                      
  6. InterviewSystem — Cooperation Default Wrong on Load
                                                                                                                                                                        File: GameState.java line 108                                                                                                                                                                                                                                                                                                               getCooperation() returns 50 as default if a suspect is missing from the map. But the constructor initializes from s.getStartingCooperation() (James=70, Charles=70,   Margaret=60, Marcus=55, Daniel=50). After a save/load, if the cooperation map partially fails to deserialize, suspects revert to 50 instead of their actual starting   values. Charles and James would silently lose their 70 cooperation starts.                                                                                         
  
  Fix: Change default to s.getStartingCooperation() instead of hardcoded 50.                                                                                            
  ---                                                                                                                                                                 
  7. HintSystem — Wrong Hint Text (Content Bug)
                                                                                                                                                                      
  File: HintSystem.java line ~91
                                                                                                                                                                        A hint says "Harold's own tape holds the first key" but references TAPE_MARGARET_INTERVIEW. Harold has no interview tape — Margaret does. This is a factual mistake   that will confuse players who follow the hint.                                                                                                                      
                                                                                                                                                                        Fix: Change to "Margaret's account holds the first key" or similar.                                                                                                   
  ---                                                                                                                                                                 
  8. ExaminationSystem — Mini-Game Can Be Replayed
                                                                                                                                                                      
  File: ExaminationSystem.java lines 87–90
                                                                                                                                                                        The cellar ashes return MiniGameType.TORN_LETTER_RECONSTRUCTION on first exam, then a repair solution on second exam. But there is no gate preventing the player      from triggering the mini-game repeatedly (exam count only gates the reward, not the mini-game trigger). A player could replay the torn letter reconstruction        
  endlessly.                                                                                                                                                          

  Fix: Check gameState.getExamCount(CELLAR, "ashes") == 1 in GameScreen before launching the mini-game.                                                                 
  ---                                                                                                                                                                   9. SaveLoadSystem — State Initialization Path Differs from Constructor
                                                                                                                                                                      
  File: SaveLoadSystem.java line ~152
                                                                                                                                                                        clearAllState() resets the cooperation map to empty, but the load path only restores cooperation from the saved JSON. If any suspect's cooperation was never          serialized (e.g., player never interviewed them and a field is missing), that suspect silently gets cooperation=50 (wrong default). The constructor path properly   
  initializes all suspects from enum starting values; the load path does not guarantee this.                                                                          

  Fix: In clearAllState() or just before populating from JSON, re-initialize cooperation from Suspect.getStartingCooperation() for any suspects missing from the save   data.
                                                                                                                                                                      
  ---
  10. InterviewSystem — Margaret Deflection Called on Margaret
                                                                                                                                                                      
  File: InterviewSystem.java line ~65 / SuspectDialogue.java line ~244
                                                                                                                                                                        getMargaretDeflection() is only called for non-Margaret suspects, but SuspectDialogue returns null if called on Margaret herself. The check in InterviewSystem        guards this… unless the cooperation threshold logic triggers it via a different path. Need to verify the deflection call is truly 100% guarded from being called    
  with Suspect.MARGARET.                                                                                                                                              

  ---                                                                                                                                                                   11. GameScreen.handleAskTopic() — NPE on Null Suspect
                                                                                                                                                                      
  File: GameScreen.java line ~1190
                                                                                                                                                                        interviewSystem.getCurrentSuspect() result is stored in currentSuspect, then used for awareness cost calculation with a null check — but                              interviewSystem.askTopic(topic) is called on line 1193 without checking if the interview is still active. If the interview ended between the null check and the call   (theoretically possible with rapid input), this produces an NPE inside InterviewSystem.                                                                            

  ---
  12. InterviewSystem — Dangerous Topic False Positives
                                                                                                                                                                      
  File: InterviewSystem.java lines 83–85
                                                                                                                                                                        Topics are flagged as "dangerous" if the string contains "cellar", "arthur", "entity", or "wall". A topic about "walter" would match "wall". A suspect named          something with "cellar" in the topic key would be flagged. No word boundary checking. Players asking innocuous questions could accidentally incur +5 awareness      
  instead of +1.
